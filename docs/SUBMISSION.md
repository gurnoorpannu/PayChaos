# PayChaos buildathon submission

## Pitch

> **AI can build a payment integration in minutes. PayChaos proves whether it
> can survive production.**

PayChaos is an AI-powered payment reliability engineer for Razorpay
integrations. It maps payment code, forms architecture-grounded failure
hypotheses, injects deterministic faults through real boundaries, evaluates
observed state against financial invariants, reconstructs the incident, exports
a regression, and replays the same failure after the control is applied.

**Submission track: [Razorpay AI Buildathon](https://razorpay.com/buildathon/),
Track 05 — Open Track.** PayChaos solves the broad problem
of payment-integration reliability rather than claiming to be a fraud or
chargeback model. AI is meaningful and bounded: it converts architecture
signals into application-specific invariants and attack hypotheses, while a
deterministic oracle alone decides whether the system failed.

## What is real in this build

| Capability | Evidence |
| --- | --- |
| Architecture understanding | Bounded multi-language scanner with evidence lines, control detection and grounded hypotheses |
| Live fault execution | `CHAOS-001` starts an ephemeral Express merchant, sends two signed HTTP requests, aborts after commit and reads target state |
| Deterministic campaigns | Duplicate, stale ordering, crash window, concurrent read/write race and forged signature, each with vulnerable and protected replays |
| Financial oracle | Typed invariants decide pass/fail from state; AI never decides financial truth |
| Razorpay boundary | Explicit ₹5 Test Mode create/fetch diagnostic; live keys are rejected before network I/O |
| Incident-to-regression | Downloadable checksummed Vitest fixture preserving signed bytes, event IDs, schedule and invariant |
| Selected-code execution | Disposable permission-restricted Node child, parent HTTP gateway, bounded CPU/memory/I/O/time and verified teardown |
| Evaluation | Eight labeled repositories; 4 TP, 4 TN, 0 FP, 0 FN and exact-label CI regression checks |

The hosted version is deliberately read-only: it replays evidence generated by
the exact live engines during deployment. Clone the repository for live
loopback execution, selected-target runs, optional AI enrichment, and a real
Razorpay Test Mode order round trip.

## Five-minute judge walkthrough

### 0:00–0:30 — Frame the failure

Open the live demo and state the distinction: ordinary tools prove the happy
path; PayChaos proves behavior after commit, timeout and retry. Point to the
**HOSTED REPLAY** label so the evidence mode is unambiguous.

### 0:30–1:10 — Show understanding and hypothesis

Use `CHAOS-001`. Show the mapped webhook → signature → fulfilment architecture,
the missing idempotency boundary, the exact source line, and the generated
Deliver → Commit → Timeout → Retry plan. Emphasize that this is a hypothesis,
not yet a finding.

### 1:10–2:05 — Prove the incident

Walk the live HTTP timeline and observed rows: the first request commits, its
acknowledgement is lost, the identical signed event retries, and two
fulfilments appear. `INV-001` deterministically observes `2`, so one ₹500
payment creates ₹1,000 of fulfilment exposure.

### 2:05–2:50 — Make it permanent and verify the fix

Choose **Download regression**, then **Verify fix**. The generated Vitest file
retains the original payload, ID, timing and oracle. The protected replay uses
an atomic unique event claim and observes one fulfilment.

### 2:50–3:35 — Show architecture-specific depth

Switch quickly through the stale-event, crash/outbox and concurrency campaigns.
The concurrency case is the strongest: PayChaos distinguishes a hopeful
read-before-write check from an atomic claim and deterministically releases two
workers after the same read.

### 3:35–4:10 — Close the scanner-to-attack loop

Choose **Scan signature demo**, show the missing-signature evidence, and launch
`CHAOS-005` from its hypothesis. The engine signs a valid raw body, changes the
amount by one paise, and proves that the stale signature either creates an
unauthorized fulfilment or is rejected before business logic.

### 4:10–4:40 — Show real boundaries

Run the bounded vulnerable and protected targets, point to network denial and
workspace removal, then show the Razorpay Test Mode connector contract.

### 4:40–5:00 — Evidence and close

Show the 46-test suite and the eight-repository exact-label evaluation, stating
the small-curated-corpus caveat. Close with the resilience score and tagline.

## Reproduce locally

Requires Node.js 22 or newer:

```bash
git clone https://github.com/gurnoorpannu/PayChaos.git
cd PayChaos
npm ci
npm test
npm run evaluate
npm run dev
```

Open `http://localhost:5173`. No credentials are required. Optional OpenAI and
Razorpay Test Mode setup is documented in [INTELLIGENCE.md](INTELLIGENCE.md)
and [RAZORPAY_TEST_MODE.md](RAZORPAY_TEST_MODE.md).
